BodyMap Pain — إصلاح الخريطة التشريحية الدقيقة + وضوح الصورة
=============================================================

سبب المشكلة (كانت الخريطة "مش بتتعلم ولا بتعطي حاجة"):
السبب الجذري في components/WebBodySilhouette.tsx — كان كل جزء تشريحي بياخد
خاصية accessibilityRole="button"، وreact-native-web بيحوّل الدور ده إلى وسم
HTML <button> حقيقي، والوسم ده مش بيعرف يرسم بيانات SVG. النتيجة: الأجزاء
بتتحوّل لعناصر غير مرئية 0×0 وضغطها لا يعمل.

الإصلاحات في هذا الملف:
1) components/WebBodySilhouette.tsx
   - إزالة accessibilityRole من كل جزء → بقى يُرسم كـ <path> حقيقي مرئي وقابل للضغط.
   - تحسين التباين (لون أوضح) وتكبير منطقة العرض.
   - تحديد أقصى عرض للخريطة حتى لا تتضخم على الشاشات الكبيرة.

2) screens/BodyPickerScreen.tsx
   - الخريطة الدقيقة (317 جزءًا) أصبحت الوضع الافتراضي على الويب لأنها الأوضح والأدق.

3) components/IllustratedBodyMap.tsx
   - تكبير إطار الصورة وتحديد أقصى عرض للحفاظ على دقة الصورة ومحاذاة العلامات.

4) public/service-worker.js
   - تحويل استراتيجية صفحة التطبيق إلى network-first حتى لا يعلق المستخدم على
     نسخة قديمة بعد كل تحديث، مع مسارات نسبية لتعمل تحت أي مسار فرعي.

5) scripts/inject-pwa.mjs
   - تحويل كل المسارات المطلقة إلى نسبية عند البناء (كانت الأصول تُطلب من جذر
     النطاق فتُرجع 403 على النشر الفرعي) + إضافة ?v=hash لكسر الكاش.

طريقة التركيب:
- انسخ الملفات إلى نفس مساراتها في مشروعك.
- npm install ثم npm run build:web
- انشر مجلد dist على Vercel أو أي استضافة ثابتة.

ملاحظة عن العدد: الخريطة مبنية على 317 جزءًا تشريحيًا دقيقًا (23 مجموعة عضلية،
ذكر/أنثى، أمامي/خلفي). لو أضفت بيانات شرائح تشريحية جديدة يمكن توسيع العدد
بسهولة لأن الخريطة تقرأ الأجزاء ديناميكيًا من مصدر البيانات.
